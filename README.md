# CyberSentinel — Enterprise Attack Path Simulation Engine

**PS10 — Generative AI for Cyber Attack Prediction**

CyberSentinel simulates realistic multi-hop attack paths through various
simulated network topologies, narrates each attack in real time
using a live LLM (Groq/Llama), and generates concrete auto-fix
remediation steps — all visualized on an interactive **3D** network
map.

This is the merged, full-stack version of the project: Person 1's
graph engine and data models, Person 2's Gen AI reasoning agent, and Person 3's
dashboard, wired together and upgraded with a real WebGL 3D scene in
place of the original 2D layout.

## What's real (Data & Graph Engine Updates)

- **Multiple Network Topologies** — Instead of one hardcoded network, the engine dynamically loads from `enterprise-bank`, `small-branch-bank`, and `legacy-iot-bank`, offering diverse simulation scenarios.
- **100% True Data via Live APIs** — Our datasets are now populated directly from the **US Government National Vulnerability Database (NVD)** and the **CISA Known Exploited Vulnerabilities (KEV) Catalog**. We utilize scripts (`generate_new_networks.py` & `fix_enterprise_bank.py`) to fetch actual vulnerability parameters instead of synthetic approximations.
- **Top-K Attack Paths & Advanced Pathfinding** — The graph engine computes and ranks the **Top-K** most dangerous paths (via Yen's / `nx.shortest_simple_paths`), rather than just returning a single route. It also features **A* search** as an alternative to Dijkstra.
- **Dynamic Weight Management (DWM) Readiness** — Nodes and CVEs have been enriched with critical context parameters (`exposure`, `kev_listed`, `patch_available`, `days_since_published`) to empower sophisticated algorithmic threat scoring.
- **The narrative and fix suggestions are really generated by an LLM**
  (Groq/Llama 3.3 by default) — not canned text. The system prompt forces
  the model to name real CVE IDs, real node names, a severity verdict, and
  (for fixes) concrete patch versions and priorities.
- **The frontend has an offline fallback** (`graphEngine.js`) that precisely mirrors
  the new Top-K logic and multi-network topologies when the
  backend is unreachable — useful for frontend-only development.

## Running it

You need **two terminals**: one for the backend, one for the frontend.

### 1. Backend

```bash
cd backend
python -m venv venv
venv\Scripts\activate          # Windows
# source venv/bin/activate     # Mac/Linux

pip install fastapi uvicorn networkx python-dotenv httpx requests

cp .env.example .env           # then edit .env and add your GROQ_API_KEY
python main.py
```

Get a free Groq key at **console.groq.com** → API Keys. If you skip this
step, the backend still runs — it just falls back to a canned "mock" LLM
response rather than a live one (still fine for testing the wiring).

Backend runs at **http://localhost:8000**. Check it's alive:
**http://localhost:8000/docs**

### 2. Frontend

```bash
cd frontend
npm install
cp .env.example .env            # defaults to http://localhost:8000, adjust if needed
npm run dev
```

Open **http://localhost:5173**.

### 3. Use it

- Pick an entry point and end goal from the dropdowns (or leave the
  defaults: Public API Gateway → SWIFT Wire Transfer Terminal).
- Click **Simulate Attack**. Watch the 3D network light up along the
  computed path while the red-team narrative streams in live.
- Once the narrative finishes, the **Auto-Fix Instructions** tab unlocks
  with concrete remediation steps for every vulnerable hop.
- Click **Risk Cards** any time to see the full CVE breakdown per node.

If the backend isn't running, the dashboard detects this and falls back
to the offline engine automatically — you'll still see a real computed
path and a template narrative, just not a live LLM response.

## The 3D upgrade

The original dashboard used a 2D node-link layout (React Flow). This
version replaces it with **`3d-force-graph`** (a Three.js-based library
purpose-built for exactly this kind of network visualization):

- Full 3D force-directed layout of all 47 nodes
- Auto-rotating camera (pauses the moment you drag/zoom, resumes after)
- Nodes colored by role (public-facing, internal, data, critical) at rest,
  and by attack state (red = compromised, orange = on the path ahead,
  dimmed = untouched) once a simulation is running
- Camera automatically flies to whichever node is currently under attack
  as the narrative streams in
- Floating labels on every node, CVE/CVSS tooltip on hover

No other component changed its props contract — `NetworkGraph.jsx` still
takes the same `{ attackPath, narrative, status, STATUS }` props it always
did, so the rest of the app didn't need to change to support the new visual.

## API contract (backend ↔ frontend)

```
GET  /networks
  → [ {id: "enterprise-bank", name: "Enterprise Bank", node_count: 47}, ... ]

GET  /options
  → { entryPoints: [...], endGoals: [...] }

POST /simulate   { "entry_node": "api_gw_1", "target_node": "swift_terminal", "network_id": "enterprise-bank", "algorithm": "dijkstra", "weighting_mode": "static" }
  → SSE stream of:
      data: {"type": "path",  "data": [ { path, nodes, total_weight, total_hops, rank, is_optimal }, ... ]}
      data: {"type": "token", "data": "next word "}   × many
      data: [DONE]

POST /fix        { "attack_path": <the exact object from the "path" event> }
  → SSE stream of:
      data: {"type": "token", "data": "next word "}   × many
      data: [DONE]
```

CORS is wide open on the backend for local development — restrict
`allow_origins` in `backend/main.py` before deploying anywhere public.

## Integration Handoff (For Persons 2, 3, and 4)

Here is a summary of the newly created files and features built by Person 1 (Data & Graph Engine) that you will hook into for your respective tasks:

*   **For Person 2 (LLM & Logic):**
    *   **`backend/dwm_scorer.py`**: A dedicated stub file has been prepared for you. The graph engine already imports it. You just need to implement your complex mathematical DWM risk formula inside `calculate_dynamic_weight()` using the true data fields we provided (`kev_listed`, `patch_available`, `days_since_published`, `exposure`).
    *   **`backend/data/networks/`**: All networks are now populated with authentic 100% true CISA/NVD data, so your LLM agents can analyze highly realistic scenarios.
*   **For Person 3 (Frontend & 3D):**
    *   **`GET /networks`**: Call this new endpoint (provided in `main.py`) to dynamically populate your Network Dropdown in the UI.
    *   **`frontend/src/data/graphEngine.js`**: We updated your offline engine to perfectly match the backend! It now returns an array of ranked paths instead of a single path, allowing you to build the UI for selecting alternative routes without relying on the live server.
*   **For Person 4 (API & Integration):**
    *   **`backend/main.py`**: We've updated the endpoints for you! `POST /simulate` now fully supports `network_id`, `algorithm`, and `weighting_mode`, meaning you just need to ensure the deployment pipelines and reverse proxies can route these SSE streams effectively.
